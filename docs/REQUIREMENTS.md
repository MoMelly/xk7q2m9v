| 标记 | 意思 |

| 🟡 | 做了一半：机制在、界面或入口缺，或者只在某一处生效 |
| ⬜ | 没做 |
| ⛔ | 明确不做（写清为什么） |

## 1. 定位（没变过）

一台只有你自己能进的假手机：亮度屏看到锁屏，解锁进桌面，图标里有信息、西瓜皮、音乐、日历、
备忘录、照片、信件、情侣空间、设置。健康没有单独一格——它能做的只有「允许角色查手机」，
已经并进「TA 的手机」底部。里面的角色按自己的作息活着，按你给的人设说话，记得你们聊过的事。

三条不能碰的边界：**一个人用**、**数据全在手机里**、**自带 API Key**。
所以账号登录、云同步、云端备份一律不做。

## 5. 这轮的设计稿

### 5.1 玻璃气泡（C-13）

同一个玻璃档，两侧用不同的底座色，靠明度差区分谁在说：

| 侧 | 底座 | 边框 | 字色 |
|---|---|---|---|
| 角色 | 黑 26% 压进玻璃 | 白 12% 描边 | 米白 100% |
| 自己 | 白 14% 压进玻璃 | 白 22% 描边 | 米白 100% |

数值落在 `MessageBubble.bubble(_:)` 的玻璃分支，两边共用 `Theme` 里的常量，不写字面值。

### 5.2 Dock（S-05）

问题不在 tint 的数值，在 `glassEffect` 按外壳的深色配色方案渲染材质——外面再垫多少白，玻璃本体还是灰的。

改法：让 Dock 这一段自己按**浅色**配色方案渲染（`.environment(\.colorScheme, .light)` 挂在玻璃之前），
tint 降到白 0.34（日间）/ 白 0.16（夜间），再补一道 0.5 白的顶部高光边。
这样出来的是一块真正透亮的玻璃，壁纸颜色能透上来，和聊天里那几颗玻璃气泡同一个档。

信息页的底栏（C-03）用同一套参数，两处看起来才是一台机器上的东西。

### 5.3 消息长按（C-20 / C-21 / C-22）

长按出菜单，两侧都能出：

| 动作 | 角色消息 | 自己的消息 |
|---|---|---|
| 复制 | ✓ | ✓ |
| 引用 | ✓ | ✓ |
| 编辑 | ✓（改他这句） | ✓ |
| 撤回 | — | ✓ |
| 删除 | ✓ | ✓ |

- 引用：输入栏上方出现一条引用条（谁说的 + 首行摘要 + ×），发出去的消息带上引用块。
- 撤回：气泡变成居中的一行小字「你撤回了一条消息」，数据库里留痕。
- 编辑：文字回填到输入框，发送时覆写这一条，气泡角上标「已编辑」。
- 数据：`StoredMessage` 加 `isRecalled` / `quoteText` / `quoteSpeaker` / `editedAt` 四个字段，全部带默认值，不动老数据。

### 5.4 打开动效（A-01 / S-21）

现在的实现是「整层缩小 + 淡入」，两个毛病都出在这：缩小的时候上边下边露出主屏，就是那道痕；首帧要把整个 App 视图建起来，动画在等它，就是那下卡。

改成**从图标位置长出来的裁剪**：

1. 点下 → 立刻把 App 层挂上，尺寸就是全屏（一次到位，不再缩），外面套一个圆角矩形裁剪。
2. 裁剪第一帧的矩形 = 你点的那个图标的位置和大小（4×6 网格算得出来），圆角 22%。
3. 下一帧开始动画：矩形长到全屏，圆角降到 0，用 `spring(response 0.36, damping 0.86)`。
4. 全程不透明度 1，没有淡入，所以不存在「露出边缝」。
5. 关闭反向：长回图标位置，期间主屏不参与动画。

### 5.5 信件（P-14 / P-15）

- 顶部分段：**全部 / 未读 / 收藏**，右侧留「按角色筛」。
- 行尾加星标，点亮即收藏；左滑也能收藏/取消（和备忘录的删除手势同一套）。
- 收藏的信在「全部」里排到未读之后、其余之前，不改变时间顺序。
- 读信页右上角也有一颗星，不用退出去点。
- 数据：`Letter` 加 `isFavorite`，解码容忍缺字段（老存档读出来是 false，不炸）。

### 8.2 几条要写清楚的做法

**小组件（S-16）** 不做成真 WidgetKit（那是系统桌面，不是我们这层壳里），是在主屏图标网格上方留一块 4×2 的区域，按 `WidgetKind` 渲染：日程（最近一件事 + 剩余几件）、天气（和角色所在地联动）、火花（连续天数 + 七天格）。数值都从现有 `WorldStore` 读，不新开一份状态。

**火花（G-14）** 只算一件事：今天两个人都说过话。另外三件小事（互相拍一拍、一起听完一首歌、写过一封信）各 +1，但**每天封顶 +1**，否则刷两下就几十天。断一天不清零 —— 从 1 重来，之前的天数进「最长」，并在断火记录里留一条。「清不清零」是这个功能唯一有分歧的地方，我按「不清零」做。

**查手机（P-22 / M-19）** 分两头：
- 前端：桌面一个 App「TA 的手机」，首页是八个图标：微信 / 相册 / 备忘录 / 通话 / 购物 / 浏览器 / 屏幕时间 / 私密。微信点得进对话，相册点得进大图，其余都是拟真列表。
- 后端：给模型的是一份**固定模板**（键名、条数、时间写法写死），让模型只填内容不设计结构。模板稳定，前端才画得出来。
- 一次生成整台手机，写进世界状态，不是进去一次现生成一次；右上角「更新」才重新要一份。
- 私密那一档默认锁着。锁着时生成也不写这一类；在设置里打开并重新生成，才会出现。

**私密这一档（P-24）** 分两种：`secret` 是瞒着你的事（借出去的钱、瞒下的麻烦、准备了没说），`private` 是只属于两个人的记录（一句话、一个场景）。提示词里对 `private` 的要求是写情绪和场景、不写身体细节 —— 尺度交给角色卡和模型，模板只定字段。

**心声（C-29）** 读 `PersonMemory.voices` 里 `isResolved == false` 的条目，按时间倒序；点开是个半屏面板，不跳页。已了结的折叠在下面。

**今日日程（P-21）** 点条目 → 半屏卡（时间、地点、同去、备注）+ 三个动作：跟他提一句 / 改时间 / 删掉。「跟他提一句」把这件事写进当前会话的输入框，不直接发。

## 9. 多角色：哪些是一个角色一份，哪些是一条世界一份

第五轮实测时你发现的：同时有好几个角色，查手机却只能查到一个人的。
顺着这条线把同类问题逐项查了一遍——**世界状态里凡是只留一个槽位的东西，
只要有第二个角色，就一定会串**。下面是对照，判过的都写在这一节里。

### 9.1 逐项

| 数据 | 原来 | 现在 | 结论 |
|---|---|---|---|
| 他的手机 | `WorldState.phone` 一台 | `phones: [CharacterPhone]`，按 `owner` 存 | ✅ 每人一台 |
| 情侣火花 | `WorldState.couple` 一份 | `couples: [String: CoupleState]` | ✅ 每人一份 |
| 记忆事实 / 心声 / 摘要 | `people` 按名字挂 | 未动 | ✅ 本来就分人 |
| 某天的时间轴 | `characterDays` 按名字挂 | 未动 | ✅ 本来就分人 |
| 信件 | `letters` 每条带 `fromName` | 未动 | ✅ 本来就分人 |
| 今日日程 | `schedule` 一份 | 仍是世界一份，但归位成「我的」 | ✅ 见 9.3 |
| 此刻心情 / 所在位置 | `mood` / `location` 各一份 | `moods` / `locations`，按角色名 | ✅ 每人一份 |
| 正在听 | `currentTrack` 一份 | 未动 | ➖ 这台手机真的只有一个播放器，不串 |
| 西瓜皮 / 市集 / 购物 / 屏幕时间 | 世界一份 | 未动 | ➖ 这些是「我自己的手机」，本来就该只有一份 |

### 9.2 这两处怎么改的

**手机**：数组按 `owner` 存，`phone(for:)` 按名字取，`savePhone` 按 `owner` 覆盖同一个人那份。
老存档里那一台在解码时自动搬进数组，不会丢。查手机页顶部多一排名字胶囊，
默认仍是「最近说过话的那个人」——从桌面图标进来时这是最合理的猜测；
从角色详情页进来则是确定的（那里多了一行「XX 的手机」）。

**火花**：`markCoupleDay` 必须带 `partner`，发消息和收回复时都传当前角色名。
老存档里那唯一一份火花没有归属，解码时先挂着；谁先开口就归给谁，只归一次。
顶部同一套名字胶囊，跟查手机共用 `NameChipStrip`。

### 9.3 日程 / 心情 / 位置（第六轮已改完）

原来这三个也是一条世界一份，表现出来是：跟 A 聊完，A 的心情会出现在跟 B 的提示词里；
A 今天的安排会被当成 B 的安排去生成 B 的手机内容。

**心情与位置**已按角色名拆开（`moods` / `locations`）。主屏和锁屏这种「只有一块地方」的界面
没有角色上下文，取 `primaryName` —— 最近说过话的那个人，跟「TA 的手机」默认打开谁同一套规则；
说一句话就换人。老存档里那两份没有归属，解出来就丢掉：心情半小时就会变，猜给谁都不对。

**日程**没有拆，反而归了位：它是**我的**。日历里的「我的」页和主屏那块「今天」都是它，
用「晨间例会 / 整理资料」那套我的工作日模板。角色自己的日子本来就在 `characterDays`，
第六轮起提示词里的【今天的安排】和手机生成都改读 `todaySchedule(for:)`，不再拿我的安排当他的。

顺带修掉一个隐蔽的问题：角色的日子原来是从 `DayScheduleEngine.generate()` 拆出来的，
那个函数的种子只有日期，谁看都排同一份。现在提示词走 `todaySchedule(for:)`，
底子是 `generateCharacterDay(name:date:)`，种子是名字 + 日期，两个人不会过同一天。
`generate()` 只留给「我的」那一份用——本来就只有一个人。
