# 界面设计规范

基准机：iPhone 15 Pro Max / 当前最新系统（iOS 26）。§4 的数值是起始值，真机截图到位后按截图校准。

这份文档只管**看起来是什么样、点起来是什么反应**；代码分层、复用、数据、构建规则在 `docs/STANDARDS.md`，不在这里重复。

---

## 1. 这份规范要解决的

2026-11-05 的 8 张截图里，日历、健康、音乐、设置四页是同一个结构：自造页头（图标 + 22pt 标题 + 说明），下面一排独立白卡，每张卡带白描边和阴影。换掉标题和文字就能当任何页面用。日历页是 6 张卡列 5 条日程，没有月份、没有日期格、没有事件色点、没有时间轴、没有底部工具栏。

代码上的原因：`ScenePage` 用一个 `row(title:subtitle:detail:symbol:)` 分发全部 8 个页面，`WhiteCard` 给每一行都铺白底 + 描边 + `radius 8 / y 3` 阴影。这套容器本身没错，错在**所有 App 都用它**，以及浅色分组列表不该有阴影。

页面之间看着割裂，不是因为它们各不相同，是因为它们共享一个不属于任何系统 App 的自造结构。

## 2. 基准设备与画布

| 项 | 值 |
|---|---|
| 基准机 | iPhone 15 Pro Max，iOS 26；`glassEffect` 可用，锁屏字形玻璃不需要低版本降级分支 |
| 逻辑画布 | 430 × 932 pt，@3x |
| 顶部 | Dynamic Island / 状态栏区按系统高度留白，自绘状态栏不压内容 |
| 底部 | Home Indicator 区 34 pt |
| 页面左右边距 | 20 pt |
| 单位 | 一律 pt，不用屏幕比例、不用百分比 |

锁屏、桌面、状态栏、Home Indicator 都是自绘的，尺寸对齐这台机器；App 内页在这个画布里按系统 App 的度量排。

---

## 3. 三条硬规则

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **一个 App 一种结构** | 日历要有日历的网格和时间轴，备忘录要有文件夹列表和搜索框，相册是照片网格。共用一个列表容器就永远是同一个页面 |
| 2 | **页面里不出现裸视觉值** | 颜色走 `Theme.*`、圆角走 `Metrics.*`、阴影走 `Theme.Shadow`、分组走组件。现在 `WhiteCard` 里写死 `Color.white.opacity(0.9)` 和 `Theme.ink.opacity(0.07)`，改一处要全局搜 |
| 3 | **深浅按 App 分，不由外壳一刀切** | `MiniPhoneApp` 的 `.preferredColorScheme(.dark)` 会翻掉所有语义色，设置页发黑、健康页开关文字变白底白字都来自这里。改成每个页面显式声明 `AppSurface` |

## 4. 视觉 Token

### 4.1 间距

| token | 值 | 用在哪 |
|---|---|---|
| `xxs` | 4 | 图标与文字、标题与副标题 |
| `xs` | 8 | 行内元素 |
| `s` | 12 | 区块内部 |
| `m` | 16 | 行内边距 |
| `l` | 20 | 页面左右边距 |
| `xl` | 24 | 区块分隔 |
| `section` | 35 | iOS grouped 分组之间 |
| `row` | 44 | 单行列表行高；带副标题 58 |

### 4.2 圆角

| token | 值 | 用在哪 |
|---|---|---|
| `grouped` | 10 | 分组列表（`.continuous`） |
| `card` | 12 | 浮层卡片、小组件 |
| `icon` | 22% 边长 | 系统 squircle 近似 |
| `pill` | 高度 / 2 | 按钮、标签 |
| `glass` | 28 | 玻璃容器 |

现在全项目统一用 16，日历页看起来像网页卡片，这是原因之一。

### 4.3 字阶

SF Pro。现有 `Theme.serif` 不用于系统 App 的界面标题，只留给信件体一类玩法文案。

| 用途 | 字号 / 字重 |
|---|---|
| 页面大标题 | 34 / bold |
| 导航标题 | 17 / semibold |
| 正文、列表标题 | 17 / regular |
| 副文、说明 | 15 / regular |
| 脚注 | 13 / regular |
| Caption、时间戳 | 12 / regular |

### 4.4 颜色

两套语义色，页面按 `AppSurface` 取，不用 `.primary` / `.secondary` 这类会跟着配色方案翻转的值。

| role | 浅色 App | 深色 App |
|---|---|---|
| 背景 | `#F2F2F7`（systemGroupedBackground） | 壁纸 + 玻璃 |
| 行 / 卡片 | `#FFFFFF` | 半透明玻璃 |
| 主文字 | `#000000` | 白 |
| 次文字 | `#3C3C43` @ 60% | 白 @ 70% |
| 分隔线 | `#C6C6C8` @ 60% | 白 @ 15% |
| tint | `#007AFF` | 现有 `Theme.mint` |
| 分组标题 | 灰 13pt | 同左 |

浅色 App：日历、设置、备忘录、相册、通话记录、健康、音乐、购物。
深色 App：信息、动态、论坛，沿用现有玻璃体系。

### 4.5 阴影

只有三档，**浅色分组列表默认不用阴影**：

| token | 值 | 用在哪 |
|---|---|---|
| `none` | 无 | 分组列表、行、卡片（默认） |
| `soft` | opacity 0.06 / radius 6 / y 2 | 浮层、小组件、看板 |
| `lifted` | opacity 0.12 / radius 16 / y 8 | 拖拽中的图标、模态 |

当前 `WhiteCard` 给每张行卡都加 `radius 8 / y 3`，在 `#F2F2F7` 底上叠出一圈灰边，这是「脏」最直接的一处。

### 4.6 玻璃

| token | 用在哪 |
|---|---|
| `glassRegular` | 容器、按钮、工具栏；iOS 26 走 `glassEffect(.regular, in:)`，低版本退 `.ultraThinMaterial` |
| `glassGlyph` | 只在锁屏数字：字形遮罩内可见，边缘折射高光 |

## 5. 组件库（唯一入口）

| 组件 | 替代什么 | 关键参数 |
|---|---|---|
| `AppScreen` | 现在的 `NavigationStack + header + 完成` | `surface`、导航标题、返回、右上角操作；不再有自造页头和药丸「完成」 |
| `GroupedSection` | 每张独立 `.whiteCard()` | 分组标题、行数组、脚注；整宽、10pt 圆角、行内分隔线、无阴影 |
| `ListRow` | `ScenePage.row(...)` | 左图标（彩色圆角 29×29）、主标题、副文、右侧 value / chevron / toggle / stepper |
| `EventRow` | 日历里的通用 row | 色点 + 起止时间 + 标题 + 地点，全天事件单独一行 |
| `CalendarGrid` | — | 周 / 月视图日期格，今天高亮、有事件的日期带点 |
| `AppToolbar` | — | 底部工具栏（今天 / 日历 / 收件箱 一类） |
| `WidgetContainer` | — | 小组件统一容器，尺寸 2×2 / 2×4 / 4×4 |
| `GlassGlyph` | 锁屏数字 | 字形玻璃遮罩 |
| `CharacterBoardView` | — | 分层立绘 + 点击热区 |

**禁止**：

- 页面里直接写 `.shadow(`、`Color(red:green:blue:)`、`cornerRadius(16)` 这类字面量
- `.whiteCard()` 包整段列表（保留给少量浮层，默认 `shadow = .none`）
- emoji 当图标（健康页的心形换成 SF Symbol 或系统彩色图标）
- 「居中大标题 + 灰色副标题」的自造页头
- 右上角药丸「完成」当唯一出口；系统 App 用返回或左上角关闭
- 每页都套同一个 `row(...)`，由 §6 的结构判据挡住

## 6. 每个 App 的结构判据

验收时逐条对，不做满不算做完。

| App | 必须有 | 不能出现 |
|---|---|---|
| 日历 | 月份标题与切换、周 / 日网格、日期数字、事件色点与时间轴、全天事件栏、右上角 +、底部工具栏（今天 / 日历 / 收件箱） | 6 张独立白卡列日程、把心情当事件标题后缀 |
| 设置 | 整宽分组列表、行内分隔线、脚注贴分组下方、彩色圆角小图标、二级页 push + 返回 | 每组一张带阴影的独立大卡、分组标题飘在卡外 |
| 备忘录 | 文件夹列表、搜索框、底部新建按钮 | 通用 row 列表 |
| 相册 | 照片网格 + 年月分组、选中态 | 列表行 |
| 通话记录 | 全部 / 未接分段控件、行内时间、右侧 info | 通用 row 列表 |
| 健康 | 摘要页 + 分类磁贴、顶部日期 | 两张白卡加大片空白 |
| 音乐 | 资料库列表 + 底部正在播放条 | 只有导入按钮和空态说明 |
| 购物 / 论坛 | 本地模板数据，按各自 App 的列表结构 | 与其他页共用通用 row |
| 信息 / 动态 | 深色玻璃、气泡、输入条 | 白色分组列表 |

---

## 7. 深浅与外壳

- `MiniPhoneApp` 不再全局 `.preferredColorScheme(.dark)`。每个 App 显式声明 `AppSurface.light / .dark / .glass`，由 `AppScreen` 注入对应语义色。
- 锁屏和桌面跟随壁纸，不受 App 内页影响。
- 语义色一律用绝对色值（`Theme` 已经这么做），不依赖系统配色方案。

---

## 8. 门禁与验收

| 项 | 做法 |
|---|---|
| 规范脚本 | `check_standards.py` 加规则：`Features/` / `Shell/` 禁止裸 `.shadow(`、裸 `Color(red:`、裸 `cornerRadius(` 字面量；场景页禁止 `.whiteCard()` 包列表；`Form` 仍然禁 |
| 截图验收 | 每次改动后 CI 出对应页面截图，逐张对照 §6；截图清单由 `fetch_artifacts.py` 动态取 |
| 新增截图状态 | `calendar`、`settings`、`health`、`notes`、`photos`、`calls`、`music`、`home`、`lock` |
| 真机校准 | §4 的数值以 15 Pro Max 真机截图为准；有出入先改 token，不改各页面 |

---

## 9. 分工

`STANDARDS.md` 管代码与工程：分层、复用表、数据迁移、构建、提交。`DESIGN.md` 管视觉与交互：token、组件库、App 结构、验收判据。改组件时两处都要看：那边决定用哪个既有能力，这边决定它长什么样。
